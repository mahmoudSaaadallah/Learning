The `UNPIVOT` operator in SQL Server is used to transform columns into rows. It's essentially the reverse operation of `PIVOT` [[T-SQL PIVOT]]. While `PIVOT` rotates rows into columns, `UNPIVOT` rotates columns into rows, making the data more normalized and often easier to analyze or store in a relational database.

### Purpose of UNPIVOT

You would typically use `UNPIVOT` when:
-   Your data is in a "wide" format (many columns representing categories or attributes) and you need to convert it to a "long" format (fewer columns, with one column for the category name and another for its value).
-   You want to normalize denormalized data.
-   You need to perform aggregations or analysis across categories that are currently stored as separate columns.
-   You want to display data in a different layout for reporting.

### Syntax

The basic syntax for `UNPIVOT` is as follows:

```sql
SELECT <non_pivoted_columns>,
       <for_column>,
       <pivot_column>
FROM
    (<source_table_or_query>) AS <source_alias>
UNPIVOT
    (
        <pivot_column> FOR <for_column> IN (<column_to_unpivot_1>, <column_to_unpivot_2>, ...)
    ) AS <unpivot_alias>;
```

### Explanation of Syntax Components

-   **`<source_table_or_query>`**: This is the table or a query expression that produces the result set you want to unpivot. It's often a subquery or a Common Table Expression (CTE).
-   **`<source_alias>`**: An alias for your source table or query. This is mandatory.
-   **`UNPIVOT`**: The keyword that initiates the unpivoting operation.
-   **`<pivot_column>`**: This is the name of the new column that will hold the *values* from the original columns you are unpivoting. For example, if you unpivot `Sales2020`, `Sales2021`, `Sales2022`, this new column will contain the actual sales figures (e.g., 100, 150, 200).
-   **`FOR <for_column>`**: This specifies the name of the new column that will hold the *names* of the original columns that were unpivoted. Using the sales example, this column would contain 'Sales2020', 'Sales2021', 'Sales2022'.
-   **`IN (<column_to_unpivot_1>, <column_to_unpivot_2>, ...)`**: This is a comma-separated list of the columns from your source table that you want to transform into rows. These are the columns whose values will populate the `<pivot_column>` and whose names will populate the `<for_column>`.
-   **`<unpivot_alias>`**: An alias for the result set generated by the `UNPIVOT` operation. This is also mandatory.
-   **`<non_pivoted_columns>`**: These are the columns from your source table that you want to keep as-is in the final result set. They are not affected by the `UNPIVOT` operation and will be repeated for each new row generated by the unpivot.

### How UNPIVOT Works

1.  For each row in the source table, the `UNPIVOT` operator iterates through the columns specified in the `IN` clause.
2.  For each of these columns, it generates a new row in the output.
3.  The new row will contain:
    *   The values from the `<non_pivoted_columns>` (repeated for each new row generated from the original row).
    *   The value from the current unpivoted column (this goes into the `<pivot_column>`).
    *   The *name* of the current unpivoted column (this goes into the `<for_column>`).

### Key Considerations and Limitations

1.  **Data Type Compatibility**: All columns specified in the `IN` clause must have compatible data types. SQL Server will implicitly convert them to the data type with the highest precedence among them. If the data types are incompatible (e.g., `INT` and `VARCHAR`), you might get conversion errors or unexpected results (e.g., numbers being converted to strings). It's often best to explicitly `CAST` or `CONVERT` columns to a common data type before unpivoting if there's a mix.
2.  **NULL Values**: By default, `UNPIVOT` **excludes** any rows where the value in the unpivoted column is `NULL`. If you need to retain `NULL` values, you'll need to handle them *before* the `UNPIVOT` operation (e.g., by replacing `NULL`s with a default value using `ISNULL` or `COALESCE`) or use an alternative method like `CROSS APPLY` with `VALUES`.
3.  **Static Operation**: `UNPIVOT` is a static operator, meaning the columns to be unpivoted must be explicitly listed in the `IN` clause. If your column names change frequently or are unknown at design time, you'll need to use dynamic SQL to construct the `UNPIVOT` query.
4.  **Performance**: For very large datasets, `UNPIVOT` might not always be the most performant solution compared to other methods like `CROSS APPLY` with `VALUES`, especially if complex data type conversions are involved. However, for readability and simplicity, it's often preferred.

### Detailed Example

Let's say you have a table storing annual sales figures for different products, where each year's sales are in a separate column:

**1. Original Table Structure and Data:**

```sql
CREATE TABLE ProductSales (
    ProductID INT PRIMARY KEY,
    ProductName VARCHAR(50),
    Sales2020 DECIMAL(10, 2),
    Sales2021 DECIMAL(10, 2),
    Sales2022 DECIMAL(10, 2)
);

INSERT INTO ProductSales (ProductID, ProductName, Sales2020, Sales2021, Sales2022) VALUES
(1, 'Laptop', 100000.00, 120000.00, 150000.00),
(2, 'Mouse', 15000.00, 18000.00, 20000.00),
(3, 'Keyboard', 25000.00, 22000.00, 28000.00),
(4, 'Monitor', 50000.00, NULL, 60000.00); -- Note the NULL for Monitor in 2021

SELECT * FROM ProductSales;
```

**Result of `SELECT * FROM ProductSales;`:**

| ProductID | ProductName | Sales2020 | Sales2021 | Sales2022 |
| --------- | ----------- | --------- | --------- | --------- |
| 1         | Laptop      | 100000.00 | 120000.00 | 150000.00 |
| 2         | Mouse       | 15000.00  | 18000.00  | 20000.00  |
| 3         | Keyboard    | 25000.00  | 22000.00  | 28000.00  |
| 4         | Monitor     | 50000.00  | NULL      | 60000.00  |

**2. UNPIVOT Query:**

Now, let's unpivot the `Sales2020`, `Sales2021`, and `Sales2022` columns into two new columns: `SalesYear` (for the year) and `SalesAmount` (for the sales value).

```sql
SELECT ProductID,
       ProductName,
       SalesYear,
       SalesAmount
FROM ProductSales
UNPIVOT
    (
        SalesAmount FOR SalesYear IN (Sales2020, Sales2021, Sales2022)
    ) AS UnpivotedSales;
```

**3. Result of the UNPIVOT Query:**

| ProductID | ProductName | SalesYear | SalesAmount |
| --------- | ----------- | --------- | ----------- |
| 1         | Laptop      | Sales2020 | 100000.00   |
| 1         | Laptop      | Sales2021 | 120000.00   |
| 1         | Laptop      | Sales2022 | 150000.00   |
| 2         | Mouse       | Sales2020 | 15000.00    |
| 2         | Mouse       | Sales2021 | 18000.00    |
| 2         | Mouse       | Sales2022 | 20000.00    |
| 3         | Keyboard    | Sales2020 | 25000.00    |
| 3         | Keyboard    | Sales2021 | 22000.00    |
| 3         | Keyboard    | Sales2022 | 28000.00    |
| 4         | Monitor     | Sales2020 | 50000.00    |
| 4         | Monitor     | Sales2022 | 60000.00    |

**Notice:** The row for `Monitor` and `Sales2021` (which had a `NULL` value) is **missing** from the unpivoted result, as `UNPIVOT` by default discards `NULL` values.

### Handling NULL Values (Alternative Approach)

If you need to include `NULL` values, you can use `CROSS APPLY` with `VALUES` as an alternative to `UNPIVOT`. This method offers more flexibility, especially with different data types or when you want to explicitly control `NULL` handling.

```sql
SELECT ProductID,
       ProductName,
       SalesYear,
       SalesAmount
FROM ProductSales
CROSS APPLY (VALUES
    ('Sales2020', Sales2020),
    ('Sales2021', Sales2021),
    ('Sales2022', Sales2022)
) AS UnpivotedSales (SalesYear, SalesAmount);
```

**Result of `CROSS APPLY` query (including NULLs):**

| ProductID | ProductName | SalesYear | SalesAmount |
| --------- | ----------- | --------- | ----------- |
| 1         | Laptop      | Sales2020 | 100000.00   |
| 1         | Laptop      | Sales2021 | 120000.00   |
| 1         | Laptop      | Sales2022 | 150000.00   |
| 2         | Mouse       | Sales2020 | 15000.00    |
| 2         | Mouse       | Sales2021 | 18000.00    |
| 2         | Mouse       | Sales2022 | 20000.00    |
| 3         | Keyboard    | Sales2020 | 25000.00    |
| 3         | Keyboard    | Sales2021 | 22000.00    |
| 3         | Keyboard    | Sales2022 | 28000.00    |
| 4         | Monitor     | Sales2020 | 50000.00    |
| 4         | Monitor     | Sales2021 | NULL        |
| 4         | Monitor     | Sales2022 | 60000.00    |

As you can see, the `CROSS APPLY` method retains the `NULL` value for `Monitor` in `Sales2021`.

In summary, `UNPIVOT` is a powerful and concise operator for transforming wide data into a long, normalized format in SQL Server, but it's crucial to understand its behavior regarding data types and `NULL` values.
